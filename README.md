# Parent-Android-Remote-Control

離れて暮らす親のスマートフォン操作を、家族がリモートでサポートするためのアプリです。

## 概要

ITに不慣れな親のAndroid端末の画面を、家族（子）の端末からリアルタイムに閲覧し、
タップ・スワイプ・文字入力を代わりに操作できます。電話で操作方法を説明する代わりに、
実際に画面を見ながらリモートで操作できることを目指しています。
（監視・ペアレンタルコントロール用途ではなく、あくまで「リモートサポート」ツールです）

## 主な機能

- 親端末の画面をリアルタイムに子端末へミラーリング（Android MediaProjection使用）
- 子端末から親端末へのタップ・スワイプ・文字入力の送信
- 親端末の通信状態（Wi-Fi等）を子端末側に表示
- 操作フィードバック用のタップ位置マーカー表示
- Windows向けPCビューワークライアント（C#/WPF）にも対応
- UIは日本語・英語・中国語に対応（端末の言語設定で自動切替）

## 使用技術

| 領域 | 技術 |
|---|---|
| Androidアプリ（親・子共通） | Kotlin、MediaProjection + `MediaCodec`（H.264エンコード）、AccessibilityService（入力注入）、フォアグラウンドサービス、ホーム画面ウィジェット |
| PCクライアント（子側） | C# / .NET 8 / WPF、Windows Media Foundation（H.264デコード） |
| 通信 | Tailscale上のTCP直接接続、独自のバイナリメッセージフレーミング |
| 対象 | Android 8.0（API 26）〜 Android 16（API 36）、Windows 10以降 |

## 動作環境

- 親側: Android（Accessibility Service権限が必要）
- 子側: Android または Windows 10以降（PCクライアント）
- 通信: Tailscale経由のP2P接続

## セットアップ

1. リポジトリをclone
2. Android Studioで `app/` を開いてビルド
3. PCクライアントを使う場合は `pc-client/FamilyRemote.PcClient.sln` を Visual Studio / `dotnet` でビルド

## 技術的なポイント

設計判断の詳細な経緯は [docs/DECISIONS.md](docs/DECISIONS.md) に記録しています（括弧内は同ファイルの項番）。

### 親側の操作を最小にする設計

- 画面共有開始時のOS確認ダイアログ（MediaProjection）は、プライバシー保護のため一般アプリからは省略できません。
  これを前提に、ホーム画面ウィジェットから共有処理を直接起動することで、親の操作を「アプリを開く → ボタン → 確認」の3タップから
  「ウィジェット → 確認」の2タップに減らしました（#1, #4）。
- Android 14以降で表示される「アプリ単位 / 画面全体」の共有選択は、画面全体の共有に固定して選択の手間をなくしています。

### 遠隔入力の実装

- 文字入力は、クリップボード経由の貼り付けや1キーずつの転送ではなく、入力済みの文字列をまとめて送り、
  AccessibilityServiceの `ACTION_SET_TEXT` でフォーカス中の入力欄へ直接設定しています。
  親のクリップボードを勝手に上書きしない、遅延の影響を受けにくい、という理由です（#9）。
- 親と子で画面比率が異なる場合は、映像を引き伸ばさず余白（レターボックス）を付けて表示します。
  引き伸ばすと見た目の位置と実際のタップ位置がずれるためです（#10）。
- 余白部分へのタッチは、近い座標に補正せず破棄します。端末の縁を持った指が触れただけの誤タッチで、
  親の画面に意図しない操作が起きるのを防ぐためです（#11）。

### 接続とバックグラウンド動作

- 接続は、親側が画面共有を開始した時点で親から確立します。親端末で常時待ち受けると、
  一部メーカー独自OSの強いバックグラウンド終了の影響を受けるため、確実に動いているフォアグラウンドサービスの
  ライフサイクルに相乗りさせています（#12）。
- 親の実機（ZTE MyOS）はバックグラウンドアプリを積極的に終了させるため、初回設定チェックリスト・自動再接続・
  共有中のスリープ防止で影響を小さくしています（#6, #8）。
- Android 11以降のパッケージ可視性制限に対応するため、`<queries>` でTailscaleアプリを明示し、
  未起動時の検出と起動ボタンを実現しています。

### PCクライアント

- 映像は親アプリ側の既存H.264プロトコルをそのまま再利用しているため、親アプリは相手がAndroidかPCかを
  区別する必要がありません（#15）。
- デコードにはFFmpegではなくWindows Media Foundationを採用しました。Windows専用と割り切ることで、
  ネイティブライブラリの同梱やLGPL対応が不要になります（#16）。
- PCでは手入力のペアリングコード（8文字、見間違えやすい文字を除外）を使います。打ちやすさのため桁数には限界があるので、
  試行回数制限と組み合わせて総当たりへの耐性を確保しています（#17）。

### 割り切った点

- 親が自分で画面を触るのと子の遠隔入力が同時に起きた場合の調停は行っていません。
  自動調停には親端末の操作体系そのものを変える必要があり、ITに不慣れな親への影響が大きいため、
  既知の制約として残しています（#22）。

## 注意事項

- `FLAG_SECURE` が設定されたアプリ（銀行アプリ等）は仕様上、子端末側で黒画面表示となります
